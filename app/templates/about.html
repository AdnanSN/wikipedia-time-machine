How it works

Wikipedia runs on MariaDB, and keeps its history in a revision table that its own software fills on every edit. This page keeps the same history without any such software. The table below is the whole mechanism.

What the last line does

WITH SYSTEM VERSIONING makes the server keep every earlier version of every row. The table holds {{ '{:,}'.format(counts.current_rows) }} current rows, one per article, and {{ '{:,}'.format(counts.all_rows - counts.current_rows) }} history rows, from {{ counts.oldest | day }} to {{ counts.newest | day }}.

row_start and row_end say when a version was the current one. Notice that the server has added row_end to the primary key, which is how many versions of one article share a page_id.

What a query adds

  • Nothing: the current rows.
  • FOR SYSTEM_TIME AS OF t: the rows as they stood at t.
  • FOR SYSTEM_TIME BETWEEN a AND b: every version current at some point in the range.
  • FOR SYSTEM_TIME ALL: every version there ever was.
  • SET system_versioning_asof = t: AS OF t for every query of the session.

Where each one is used here

  • Articles: the whole list travels with one SET.
  • An article: one AS OF. The picture above the text is FOR SYSTEM_TIME ALL.
  • What changed: two AS OF moments in one query.
  • When did it say that: a window function over FOR SYSTEM_TIME ALL.
  • Lab: edit a page and watch the server write the history.

Every page prints the SQL it ran, at its foot. The dates are Wikipedia's own save times; how they got into a column that the server normally fills from its clock is the main design decision of the project, explained in the write-up.
